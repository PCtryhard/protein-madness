# Rescored designs (round 2, geometry re-rank)

All 314 scored designs that have a committed structure, re-scored on catalytic
geometry, with their predicted complexes copied here under a traceable name.

> **Two batches.** 232 designs came from the overnight and depth runs; the last
> commit added the **82 from `data/final_run_60/`** and regenerated the tables
> over all 314. The rest of this file was written for the first 232 and has
> been brought up to date — the counts below are recomputed from
> `manifest.csv` as it stands.

Produced from `scripts/rerank_geometry.py` at commit `5177aeb`, patched as
described below, run with `--min-score 0 --include-legacy`. Nothing was
refolded: this is a pure re-score of structures already in the repo, so it
costs no GPU and is reproducible.

## Contents

| path | what it is |
| --- | --- |
| `cif/` | 314 predicted complexes, renamed (scheme below) |
| `manifest.csv` | one row per file: new name, original `design_id`, run, lineage, scores |
| `rerank_geometry.csv` | the re-rank table, 314 rows |
| `rerank_geometry.json` | run metadata: the weights, the module constants, and the wildtype reference check (not the table) |
| `rerank_round2.html` | browsable leaderboard with a 3D structure viewer; the tables work offline, the viewer needs a network connection. **Shows only the first 232** — see below |

## Viewing the structures

> **`rerank_round2.html` is frozen at the first 232 designs.** Its data is
> inlined in the page, it was hand-built rather than generated by anything in
> `scripts/`, and it was not rebuilt when the 82 final-batch designs landed —
> so it still names `01_s_95cdcf` the leader. For a viewer over all 314, build
> the pocket inspector, which reads `manifest.csv` and `rerank_geometry.csv`
> off disk every time:
>
>     python scripts/pocket_inspector/build_inspector.py

`rerank_round2.html` embeds a 3Dmol.js viewer. Ligand in ball and stick,
protein as ribbon, and every residue within the contact radius of the ligand
rendered as sticks over the ribbon, plus the named catalytic residues however
far away they sit. Everything is coloured by element throughout. The contact
radius defaults to 3 A as heavy-atom to heavy-atom; these structures carry no
hydrogens, so that shell is thin, typically 2 to 6 residues. Around 4.5 A
gives a readable pocket.

Two things to know:

- **The viewer library comes from a CDN**, so that panel needs a network
  connection. The tables, the chart and the leaderboard are all inline and
  work with no network. The library cannot be bundled from here because this
  environment has no outbound network for package downloads.
- **Opened straight from disk, the browser will not read neighbouring
  files.** The viewer first tries `cif/<name>` when the page is served over
  http, then falls back to the raw GitHub URL. If neither works, use the file
  picker at the bottom of that section, or serve the folder:

      cd data/rescored && python3 -m http.server
      # then open http://localhost:8000/rerank_round2.html

## Naming scheme

    XX_yyyyy_zzzzzz.cif

- `XX` — seed variant, `01` to `13`.
- `yyyyy` — one character per adjustment in the design's ancestry, oldest
  first: `m` for mutate, `w` for wiggle. So `mwm` is a design that was
  mutated, then wiggled, then mutated again. A cycle-0 seed had no
  adjustment and is written `s`.
- `zzzzzz` — the six hex digits the pipeline puts at the end of every
  `design_id`.

Examples:

    01_s_95cdcf.cif     variant 01, unadjusted seed
    01_w_865ea3.cif     variant 01, one wiggle
    02_mwm_cce984.cif   variant 02, mutate then wiggle then mutate
    08_wmm_25a996.cif   variant 08, wiggle then mutate then mutate

All 314 filenames are unique. **The hex ids are not** — 311 of the 314 are
distinct, and three designs from `data/final_run_60/` drew a hex that an
earlier batch had already used. Those three carry a `_2` suffix:

| hex | the two designs that share it |
| --- | --- |
| `20d882` | `06_mm_20d882.cif` (depth-06) and `06_mm_20d882_2.cif` (07-06-36badf) |
| `995a1f` | `06_m_995a1f.cif` (depth-06) and `06_m_995a1f_2.cif` (07-06-36badf) |
| `e943af` | `01_m_e943af.cif` (overnight-01) and `01_m_e943af_2.cif` (01-01-95cdcf) |

So the **filename** identifies a design; `zzzzzz` on its own does not. Use
`design_id` or the `run` + `hex_id` pair from `manifest.csv` when it matters.

## The lineage is the parent chain, not the cycle number

Reconstructed by walking `parent_id` through each run's `designs.csv` and
recording the `branch` of every non-seed ancestor.

**The number of adjustments is not the cycle number**, and it can fall on
either side of it:

- **Shorter than the cycle** for **60** designs. The search re-expands the seed
  at every cycle, so a design labelled `c03` may descend from the seed through
  only one or two adjustments.
- **Longer than the cycle** for **42** designs, all of them from
  `data/final_run_60/`. That batch restarted the cycle counter at 0 from a
  parent that was already several adjustments deep, so a design labelled `c01`
  there can carry four adjustments of real ancestry.

| cycle | adjustments | designs |
| --- | --- | --- |
| 0 | 0 | 90 |
| 1 | 1 | 83 |
| 1 | 2 | 13 |
| 1 | 3 | 3 |
| 1 | 4 | 3 |
| 2 | 1 | 19 |
| 2 | 2 | 24 |
| 2 | 3 | 11 |
| 2 | 4 | 4 |
| 3 | 2 | 32 |
| 3 | 3 | 12 |
| 3 | 4 | 5 |
| 3 | 5 | 1 |
| 4 | 2 | 2 |
| 4 | 3 | 7 |
| 4 | 4 | 3 |
| 4 | 5 | 2 |

The filename records the adjustments actually performed. Naming from the cycle
number instead would claim adjustments that never happened for those 60, and
hide real ones for the other 42. `search_cycle` and `adjustments` are both
columns in `manifest.csv` if you need to tell them apart.

## The patch this run depended on

The first re-rank pass skipped every `fastrelax-*` run, which removed 29
designs including all 12 of variant 12's hits. The reason was real but the
remedy was wrong.

The two run families write different columns:

| | `fastrelax-*` | `overnight-*`, `depth-*` |
| --- | --- | --- |
| weights | conf 0.70 / geom 0.30 | conf 0.50 / geom 0.50 |
| geometry split | distance 0.60 / angle 0.40 | catalytic 0.50 / non_catalytic 0.20 / angle 0.30 |
| columns | `term_distance`, `term_angle` | `term_catalytic`, `term_non_catalytic`, `term_angle` |

`old_geometry()` looked only for the newer column names. On a `fastrelax` row
it matched `term_angle` alone, renormalised over that single weight, and
returned the angle as the entire geometry composite, silently discarding the
distance. Running `--include-legacy` without the patch would therefore have
inflated those designs: variant 12's best would have taken `hbond = 0.934`
instead of `0.732`, scoring 0.778 instead of 0.717 and placing about third.

`rerank_legacy_layout.patch` adds a branch that rebuilds the composite as
`0.6 * distance + 0.4 * angle` at that run's own weights. It is recorded here
for reproducibility and is **not** applied to `scripts/rerank_geometry.py` —
apply it there before re-running if you want these numbers back.

## The wildtype scores worse than a top design

`rerank_geometry.json` records a consistency check against the wildtype fold
(`data/01/inputs/fold_wildtype_ligand_model_0.cif`), comparing it to
`01_s_95cdcf` — which led the first 232 and now sits **third** of 314, behind
two designs from `data/final_run_60/` (`01_mmmm_d8aad7` at 0.813 and
`01_mmm_660e17` at 0.8043). It comes out at

| term | wildtype | `01_s_95cdcf` |
| --- | --- | --- |
| planarity | 0.607 | 0.780 |
| cat_polarity | 0.940 | 0.84 |
| apolar_match | 0.900 | 0.78 |

The wildtype's own His263 to ligand-N1 contact is 3.77 A long and sits 2.35 A
out of the ring plane, which is why its planarity term is only 0.61. So the
top design scores *above* the reference on the term that did most of the
reshuffling.

Read that as a caution about the term, not a result about the design. Either
the planarity penalty is harsher than real enzymes require, or this reference
is not a fair yardstick: it is a Boltz fold of the wildtype rather than the
crystal structure. The file's own caveat also notes that `cat_polarity` was
revised after this reference was inspected, which makes it a consistency
check and not a validation. Worth settling against the 5FQJ crystal geometry
before anyone treats the absolute values as meaningful.

## Known limits

- **The hbond slice is not perfectly uniform.** It is each row's own pipeline
  definition of the geometry composite. The confidence term is identical in
  both configs (`complex_ipde` ramped 0.5 to 5.0 A), and planarity,
  cat_polarity and apolar_match are recomputed from the structures the same
  way for every design. So roughly 70 % of the score is strictly comparable
  and 30 % approximately so. Recomputing the hbond composite from the
  structures with one definition would close this.
- **Two scored designs are absent.** `02.c01.wiggle.4b0d78` and
  `02.c01.wiggle.6d5166` have no committed structure: Boltz served them from
  cache as duplicates of `4642b0`, so nothing was written to re-score.
- **Round 1 scores mix two scales.** `old_score` and `old_rank` in the
  re-rank table come from each run's own config, 29 of them on the
  confidence-heavy 0.70/0.30 formula. Use `new_score` for ranking; treat
  `old_score` as a per-run gate check.
- **Variant 01 is flattered by having only two bonds.** Its designs average
  their terms over two contacts rather than three, and the missing one is the
  nitro contact, the weakest across every variant. Designs with two measured
  contacts average 0.633; those with three average 0.581.
